# Directory synchronization

The directory uses Webex People, Workspaces, Calling Numbers, and Locations, with complete pagination and the configured tenant. Sync runs every three hours (17 minutes past 00, 03, 06, 09, 12, 15, 18, 21 UTC). The existing five-minute maintenance trigger performs the first sync and each sync-version upgrade once. Operators can also choose **Sync now** on the directory page.

First sync links existing entries by unique email or exact normalized display name. It never guesses using an extension that could have been reassigned. Subsequent runs use the saved Webex identity, updating name, primary phone, extension, email, location and the Location line in notes. Other note content is retained. Explicit extension-only assignments clear the old external phone. Unreported fields are retained.

Every entry whose trimmed first name starts with WG (case insensitive) is excluded before matching, updates, or deletions. Previously linked entries missing from complete source lists are removed. Missing Webex users/workspaces with a phone or extension are automatically added by stable identity. Assigned voicemail groups, virtual lines, call queues, Contact Center adapter numbers, auto attendants and paging groups are also included from the number inventory. Hunt groups remain managed through the protected WG rows. Unassigned number inventory and identities without a phone/extension are not added. Ambiguous legacy matches remain untouched and their candidate identities are held for review. Repeated syncs do not duplicate entries.

Directory data is serialized in the existing companion Durable Object class under a dedicated `orgId:directory:v1` object, separate from callback settings and execution. That object receives a DIRECTORY_KV binding. It initializes from the existing directory, keeps revision backups, and publishes the existing KV mirror. Directory JSON/XML reads use the same canonical state. Manual saves require the revision loaded by the editor; stale saves return 409. The UI retains Webex identity through edits and blocks manual sync while unsaved edits exist.

Deploy with scripts/integrate-directory-sync.mjs over the current live Worker modules, preserving unrelated live changes. The companion adds directory-sync/store.mjs and directory-sync/sync.mjs, inherits existing bindings/migration tag and adds DIRECTORY_KV. The main adds directory-sync/sync.mjs and the three-hour cron without removing existing schedules. Keep backups and remove the new cron before any rollback; avoid switching the main back to legacy KV writes after canonical directory edits have begun.

On 2026-10-15, the owner approved excluding the 35 legacy unmatched/ambiguous entries from the initial sync. A one-time migration removes only exact fingerprints of those approved rows, skips all WG and Webex-linked rows, backs up the prior revision, and updates both canonical storage and the KV mirror. Later edits do not match the approved fingerprints. Deploy the companion with `directory-sync/legacy-cleanup.mjs` alongside `store.mjs` and `sync.mjs`.

Version 2 automatically backfills assigned Webex entries and reports additions in the UI. Deployment updates only directory-sync/sync.mjs in the main Worker and sync.mjs/store.mjs in the companion, preserving all other current live modules. The previously removed legacy names are not restored; their current authoritative Webex records are inserted when assigned.
